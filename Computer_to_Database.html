计算机组成原理：机器到底是怎么“动”起来的

这一章只回答一个问题：一块沙子做的芯片，凭什么能算数、能放视频。

整章用一个比喻：把电脑想成一家工厂。有工人、有工位、有手边的小料盒、有车间货架、有厂外仓库、有传送带、有节拍器。所有名词都是这家工厂里的一件东西。
晶体管Transistor
一个能被电控制通断的开关。通电代表 1，断电代表 0。一颗现代芯片里塞了几百亿个。它本身什么都不会，但堆多了就能表达一切。作用：它是整个数字世界的原子。没有它，就没有 0 和 1。
门电路 / 逻辑门Logic Gate
几个晶体管搭在一起，能做“两个都满足才输出 1”（与）、“满足一个就输出 1”（或）、“反过来”（非）。作用：把开关变成“判断”。所有加法、比较、判断，本质上都是这几种门在组合。
二进制Binary
只用 0 和 1 计数。人用十进制是因为有十根手指，机器用二进制是因为开关只有两个状态，最不容易出错。作用：让“电”能表示“数”，再让“数”表示文字、图片、声音——一切都是编号。
ALU 算术逻辑单元Arithmetic Logic Unit
CPU 里真正“算”的那个工位，负责加减乘除和比较大小。作用：所有计算最终落到它身上。你写的 a + b，最后就是它在通电。
寄存器Register
CPU 手边几个仅有的小抽屉，一共就几十个，每个装一个数。速度最快，容量最小。作用：ALU 要算的数和算完的结果，必须先放这里。CPU 只能对寄存器里的东西动手。
缓存 Cache（L1 / L2 / L3）
工位旁边的小书架。比抽屉远一点，比仓库近得多。L1 几 KB 且只有一两个周期，L3 几十 MB 要走十几个周期。作用：CPU 每秒能算几十亿次，内存却慢一个数量级。缓存就是用来“垫住这个速度差”的，否则 CPU 大部分时间在干等。
内存 RAMMemory
车间地面上的大料架。容量大（8G/16G/32G），通电才记得住，一断电全忘。作用：装正在运行的程序和数据。你开的微信、浏览器、游戏，全摊在这里。
硬盘 / 固态硬盘HDD / SSD
厂外的仓库。容量极大、断电还在、但取东西慢。作用：长期保存。你的照片、系统、代码都在这。
总线Bus
厂区里的传送带和通道，CPU 和内存、硬盘、显卡之间的所有搬运都走它。作用：决定了“搬东西”的上限。通道窄，零件再快也供不上。
指令集ISA，如 x86 / ARM
工人能听懂的指令手册。同一个意思，x86 和 ARM 说的是两种方言。作用：决定一个程序能不能在这台机器上跑。你手机（ARM）装不了电脑（x86）的 exe，就是这个原因。
时钟频率Clock，GHz
车间的节拍器，3GHz 就是每秒三十亿拍，每拍大家动一下。作用：给所有零件对表。但注意——频率高≠更快，还要看每一拍干几件事（IPC）、缓存够不够、会不会卡在等内存上。
流水线Pipeline
把“取指令 → 译码 → 执行 → 写回”拆成四道工序，像流水线一样同时开工。作用：不用等一条指令全做完才做下一条，吞吐量翻几倍。代价是遇到“跳转”可能白干一场（分支预测失败）。
冯·诺依曼结构von Neumann
“程序和数据放在同一个仓库里”的设计。作用：这是电脑能“通用”的根本——换个程序，同一台机器就能干完全不同的事。代价是取指令和取数据抢同一条通道，叫“冯·诺依曼瓶颈”。
GPU 显卡Graphics Processing Unit
CPU 像8 个博士，能做复杂推理但人少；GPU 像几千个小学生，只会简单加减但能同时开工。作用：图像每个像素、矩阵每个元素的计算方式都一样，正好适合“人海战术”。这就是为什么训练 AI 必须用显卡，而不是 CPU。
用在哪（你每天都在碰）：
· 手机开了二十个 App 之后开始卡 → 内存不够，系统把不用的内容往存储里搬（swap），来回搬就卡。
· 玩 3A 游戏必须好显卡 → 每帧几百万个像素要同时上色，全靠 GPU 并行。
· 同一段代码，改一下数据访问顺序就快 10 倍 → 因为原本每个数都要跑去内存拿，现在都待在缓存里。
· AI 服务器为什么贵得离谱 → 贵在显存和算力，不是贵在“智能”。

数据结构：数据怎么“摆”，决定你快不快

同样一万条数据，摆放方式不同，取用速度能差几万倍。就这么现实。

整章比喻：你家有 1000 件东西。全堆在地上（乱放）、按编号排进连号柜子、每人手里拿着下一个人地址（链条）、按名字首字母分格（哈希）、按类别做成树状目录——找同一件东西的时间，天差地别。数据结构研究的就是“怎么摆”。
数组Array
一排连号的储物柜，1 号在 2 号旁边，地址是算出来的。作用：知道编号就能直接开柜门（第 500 号一秒钟到），但中间插一件，后面全部要挪位。特点：查得快，改得慢。
链表Linked List
每个人手里拿着下一个人的地址，不挨着站。作用：加人、走人都只改两个人的手，特别省事；但找第 500 个得一个个问过去。特点：改得快，查得慢。
栈Stack，后进先出
一摞盘子，最后放上去的最先拿走。作用：处理“必须原路返回”的事情。典型场景：Ctrl+Z 撤销（撤销最近一步）、浏览器的后退、程序里函数调用（A 调 B，B 调 C，C 先结束）。
队列Queue，先进先出
排队买奶茶，先来的先做。作用：处理“要按顺序、不能插队、还不能把人挤爆”的事情。典型场景：打印机任务、双十一订单排队入库、消息队列（秒杀一瞬间来 100 万请求，先塞进队列慢慢消化，不然服务器直接躺）。
哈希表Hash Table
给每个名字算一个柜号（哈希函数），直接跳过去取，不用翻。作用：查东西接近“瞬间”。代价是柜子会撞车（两个名字算出同一个号），需要一套冲突处理；装太满了还要整体扩建（rehash），那一下很慢。典型场景：字典查词、手机通讯录按名字找人、网站把网址映射到 IP、缓存。
树 / 二叉搜索树 / 平衡树Tree / BST / AVL / Red-Black
像公司组织架构，一层层往下找，每往下一层范围砍一半。左小右大是二叉搜索树；树长歪了（变成一条线）就退化成链表，所以要用平衡树自动调整。作用：有序数据的快速查找、插入、范围查询。典型场景：文件目录、数据库索引、代码里的有序集合（C++ map / Java TreeMap）。
B+ 树B+ Tree
专门为“硬盘”设计的矮胖树：一个节点塞几百上千个 key，三层就能管住几千万行数据。作用：硬盘一次读一大块最划算，所以节点要胖；层数少就少读几次盘。这就是为什么数据库几亿行还能毫秒级查出一条记录——没建索引，它就得一行行扫（全表扫描），几秒都出不来。
堆Heap，优先队列
只保证一件事：最上面那个永远是最大（或最小）的，下面谁大谁小不管。作用：随时要“当前最大/最小的几个”时极快。典型场景：游戏排行榜 Top 10、任务调度里“最紧急的先做”、导航算法里“先走最近的点”。
图Graph
点 + 连线，专门表达“关系”。谁能到谁、多远、多贵都行。作用：处理网络型问题。典型场景：地图导航算最短路线、外卖派单、社交平台“你可能认识的人”、微服务之间的调用依赖、地铁换乘。
时间复杂度 O(…)Big-O
衡量“数据量翻倍时，耗时会怎么涨”的尺子，不是测秒数。
O(1) 常数：多少数据都一样快（哈希查表）
O(log n) 每步砍一半：100 万条只要 20 步（二分查找、B+ 树）
O(n) 一条条过：100 万条就 100 万步（遍历）
O(n log n) 好排序的下限
O(n²) 双重循环：100 万条就是 1 万亿步，直接不可能跑完
作用：让你在写代码前就知道会不会崩，而不是上线后被老板骂。
用在哪：
· Ctrl+Z 撤销 → 栈　· 打印机排队、双十一削峰 → 队列
· 微信通讯录搜人名、网址查 IP → 哈希表
· 聊天记录往上翻页、文件夹层级 → 树
· 排行榜、抢红包“最快的那个先得” → 堆
· 高德算最快路线、抖音推荐关系 → 图
· 数据库不建索引慢 100 倍 → 因为它从 B+ 树退化成了全表扫

计算机网络：数据是怎么从 A 跑到 B 的

你可能没意识到，你每点一次手机，背后是几十台机器在接力。

整章比喻：寄快递。分层就是一层管一件事：你说的内容（应用层）、怎么保证送到（传输层）、写地址选路线（网络层）、真正在路上跑的车（链路/物理层）。每一层只管自己那摊事，只跟对面同层对话。这就是网络为什么能这么复杂还不乱。

先看四层，一眼就懂

应用层
HTTP / HTTPS / DNS / SMTP / WebSocket —— 你说的“话”本身：“我要这个网页”“我要发这封邮件”
传输层
TCP / UDP —— 怎么送：挂号信（必到、可查）还是明信片（快、丢了不管）
网络层
IP / 路由 —— 门牌号和路线：从北京到深圳，走哪几站中转
链路 / 物理层
以太网 / Wi-Fi / 光纤 / 4G-5G —— 真正跑的车：网线、无线电波、光
IP 地址IPv4 / IPv6
互联网上的门牌号。IPv4 只有约 42 亿个，早就分完了，所以有了 NAT 和 IPv6。作用：全球定位一台设备。没有它，你的数据不知道往哪送。
端口Port
门牌号后面的房间号。一台服务器只有 1 个 IP，但能同时跑网站、邮件、数据库。作用：区分同一台机器上的不同服务。80/443 是网页，22 是远程登录，3306 是 MySQL，6379 是 Redis。
DNSDomain Name System
互联网的电话簿，把 www.taobao.com 翻译成 203.x.x.x。作用：人记名字，机器认数字。DNS 一慢，全网页都在转圈——这就是“网络没问题但网站打不开”的常见原因。
TCPTransmission Control Protocol
可靠传输。发之前先三次握手确认“你在吗、我在、好开始”；每发一段要对方回执，丢了就重发，顺序乱了帮你排好。作用：保证一个字都不少。代价是慢一点。用在：网页、文件下载、转账、聊天消息。
UDPUser Datagram Protocol
发了就不管，不握手、不重发、不排序。作用：极快、极省。丢一两帧你根本看不出来，但卡一下你就抓狂——所以直播、视频通话、在线游戏、DNS 查询都用它。
HTTP / 状态码HyperText Transfer Protocol
网页的点菜话术。GET 是“我要”，POST 是“我交给你”，PUT/DELETE 是改和删。
状态码：200 成功、301/302 搬家了、403 你没权限、404 没这东西、500 服务器自己崩了。作用：让全世界几十亿台机器用同一套语言说话。
HTTPS / TLS加密
HTTP 外面套了一层加密信封。作用：三件事——防偷看（别人抓包只看到乱码）、防篡改（改一个字节就验不过）、防冒充（证书证明“这真是淘宝”）。浏览器地址栏那个小锁就是它。没有它，你在咖啡店连 Wi-Fi 输密码等于广播。
Cookie / Session / Token登录态
网站怎么记住“你已经登录了”。HTTP 本身是失忆的，每次请求都像第一次见面。
Cookie = 服务器塞给你浏览器的一张小纸条；Session = 服务器自己留档的档案；Token（如 JWT）= 一张自带签名的通行证，服务器不用查档也能验。作用：不让你每个页面都重新登录一次。
路由器 / 交换机Router / Switch
交换机 = 房间里的插线板，管同一张局域网内的分发；路由器 = 路口交警，决定跨网络往哪个方向走。作用：一个管“内部送达”，一个管“出门问路”。
NAT网络地址转换
让全家十几台设备共用一个公网 IP 出门，回来时再按小本本分给各台。作用：缓解 IP 不够用，顺便挡住外面的主动连接（你家电脑默认外面进不来）。
CDN内容分发网络
把视频、图片提前复制到离你最近的仓库（边缘节点）。作用：你在广州看视频，不会跑去北京的服务器拿数据。这就是为什么同一个视频，国外网站卡、国内平台秒开。
带宽 / 延迟 / 丢包Bandwidth / Latency / Loss
带宽=管子有多粗（一次能过多少）；延迟=路上要多久（ping 值）；丢包=掉了几件（要重发，表现为“卡一下”）。作用：下载电影看带宽，打游戏看延迟，视频通话看丢包。三个是不同的事，别混。
防火墙 / VPN / 代理Firewall / VPN / Proxy
防火墙 = 门卫，按规则放行或拦下；VPN = 加密隧道，让你像在公司内网一样访问；代理 = 找个中间人代办，你的请求先给它，它再帮你转。作用：安全隔离和访问控制。
WebSocket长连接
普通的 HTTP 是“你问一句我答一句”，说完就挂。WebSocket 是打通电话不挂，双方随时能说话。作用：聊天室、股票行情、协同编辑、游戏——需要服务器主动推给你的场景。

单片机：让代码真的伸手去碰这个世界

电脑只会算，单片机还会“摸”和“动”。

一句话：单片机是一台只有指甲盖大、几块钱、能连续跑十年不关机的小电脑。它内存小得可怜，但有一个电脑没有的本事——它的“脚”能直接输出电压，能读到电压。所以它能点灯、能转电机、能读温度。
单片机（MCU）

几块到几十块。内存几 KB 到几 MB。跑裸机程序或 RTOS。特点：实时、省电、稳定。代表：STM32、ESP32、51 系列、Arduino。

树莓派（SBC）

几百块。跑完整 Linux，能装 Python、OpenCV、跑小模型。特点：能干活但费电、启动慢。适合“要算力又要接硬件”的场景。

GPIO通用输入输出引脚
芯片上一根能读能写的“电脚”。写 1 输出 3.3V，写 0 输出 0V；反过来也能读外面是高还是低。作用：这是单片机和物理世界握手的地方。点 LED、读按键、驱动继电器（进而控制 220V 电器）、读传感器开关，全靠它。
ADC模数转换
现实世界是连续的（电压可以从 0 慢慢升到 3.3V），芯片只认离散的数字。ADC 就是把 1.65V 翻译成“2048”的那个翻译官。作用：读电池电量、读电位器旋钮、读光敏电阻、采集麦克风波形。没有 ADC，单片机就是聋子瞎子。
DAC数模转换
反过来，把数字变成电压。作用：输出音频、输出可控的模拟电压。
PWM脉宽调制
只会开和关，怎么调“半亮”？快速开关——一秒钟开关一千次，开的时间占 30%，看起来就是 30% 的亮度。作用：调 LED 亮度、调电机转速、控制舵机转到某个角度、控制加热功率。便宜又高效。
UART / I2C / SPI三种通信口
单片机和别的芯片“说话”的三种方式。
UART：两根线，一对一，简单可靠（调试打印、GPS 模块、蓝牙模块）。
I2C：两根线，能挂一串设备，每台有地址（温湿度传感器、屏幕、EEPROM）。
SPI：四根线，速度快（屏幕、Flash、SD 卡）。
作用：让一颗几块钱的芯片能接上几十种传感器和外设。
中断Interrupt
程序正在跑，突然按键按下/串口来数据/定时到点，硬件强行打断，跳去处理，处理完回来接着跑。作用：不用死等。没有中断，单片机只能“一直盯着按钮看”，什么都干不了。
定时器Timer
硬件闹钟，精确到微秒。作用：精确定时、产生 PWM、测量脉冲宽度（比如超声波测距）。
看门狗Watchdog
一条定时喂的狗。程序正常就每隔一会儿喂它一次；程序卡死了没喂，狗就咬人——自动重启芯片。作用：无人值守设备（电表、摄像头、汽车 ECU）的救命符。
固件 / 烧录Firmware / Flash
写进芯片里的程序叫固件，把它写进去的过程叫烧录。作用：单片机的程序是“焊死”在设备里的，不像电脑能随便装软件——所以升级固件（OTA）是一件很谨慎的事。
RTOS实时操作系统，如 FreeRTOS
单片机上的“小操作系统”，让多个任务看起来同时在跑（读传感器、刷屏幕、发数据），并且保证高优先级任务到点就能执行。作用：程序复杂到一定程度，裸机写不下去，就得上它。
用在哪（你身边全是）：
· 电饭煲：温度 ADC + 继电器控制 + 定时器 + 保温逻辑
· 电动牙刷：PWM 调马达振动频率、按键中断、低功耗待机几个月
· 共享单车锁：4G 模块（UART）+ GPS + 电机锁 + 电池电量 ADC
· 汽车：一辆车里几十上百个单片机，管气囊、ABS、车窗、空调
· 你的困倦检测项目做成产品：摄像头 + 树莓派跑人脸关键点，判定闭眼超时就通过 GPIO 拉响蜂鸣器、PWM 调震动马达强度、串口通知座椅振动模块——这些“动作”都得靠单片机落地。

AI：机器到底是怎么“学会”的

先把三个最容易搞混的词分开，后面全都通了。

模型 = 一个巨大的函数

输入一张图，输出“这是猫，87%”。它内部有几十亿个可以调的旋钮（参数）。它就是一堆数学运算，一点都不神秘。

训练 = 调旋钮

给它几百万个例子，它先瞎猜，猜错就按“错得多离谱”往回拧旋钮，重复几百万次。这个过程极慢极贵。

推理 = 用调好的模型

旋钮定死不动了，直接拿去答题。你平时用 AI 聊天、拍照识物，全是推理。推理不需要显卡集群，训练才需要。

参数 / 权重Parameters / Weights
模型里的那些数字。几十亿到上万亿个。它们就是“学到的东西”本身。所谓“7B 模型”，就是 70 亿个参数。参数越多一般越聪明，但也越慢越贵。
数据集 / 标注Dataset / Label
例子本身，以及“正确答案”。一张图 + “这是猫”就是一条带标注的数据。作用：模型只能从数据里学，数据烂，模型一定烂。行业真相：AI 项目 80% 的时间在做数据，不是在做模型。
特征Feature
数据里“有用的那部分信息”。以前靠人手工设计（量眼睛多宽、数边缘），现在深度学习自己从原始像素里学。作用：决定模型的上限。
损失函数Loss Function
一张打分表，算“你答的离标准答案差多远”。差得越多，loss 越大。作用：训练的唯一指挥棒。loss 不降，说明模型没学到东西或者数据有问题。看懂 loss 曲线是调模型的入门功。
梯度下降 / 学习率Gradient Descent / Learning Rate
想象你被蒙眼放在山上，要走到谷底。你只能用脚探一下哪边更低，然后往那边迈一步——这就是梯度下降。学习率就是步子大小：太大直接跨过谷底来回震荡，太小学到天荒地老，还可能卡在半山腰的坑里（局部最优）。
反向传播Backpropagation
从“答案错在哪”往回倒推，算出每一个旋钮该负多少责任、该往哪边拧多少。作用：这是深度学习能成立的数学基础。没有它，几十亿参数根本不知道该调哪个。
过拟合 / 欠拟合Overfit / Underfit
过拟合=把练习册答案背下来了，一换新题就废（训练集 99%，真实场景 60%）。欠拟合=太笨，练习册都没学会。对策：过拟合就加数据、加正则化、dropout、早停；欠拟合就换更大模型、训更久、加特征。
训练集 / 验证集 / 测试集
练习题 / 模拟考 / 高考。作用：用没见过的题检验真本事。如果拿考试题当练习题，考 100 分也毫无意义——这是新手最常犯的错（数据泄漏）。
监督 / 无监督 / 自监督 / 强化学习
监督：每题都有答案（识别猫狗）。无监督：没答案，自己找规律（把用户分成几群）。自监督：从数据本身挖答案，比如“遮住一个词让模型猜”——大模型预训练就是这么干的。强化学习：不给答案，只给奖励，自己试错（下围棋、机器人走路）。
神经网络 / 激活函数Neural Network / ReLU
一层层的“神经元”，每层做的事就是加权求和 + 过一下激活函数。激活函数（如 ReLU：负数变 0，正数不变）看着很傻，但它是关键——没有它，堆一万层也只等价于一层，学不会任何复杂东西。
CNN 卷积网络Convolutional Neural Network
拿一个小窗口在图上滑动扫，先找出边缘，再拼出纹理，再拼出形状，最后拼出“猫脸”。作用：图像识别的老功臣，人脸识别、车牌识别、工业质检全靠它。你项目里如果不用 dlib 的现成关键点，多半就是训一个 CNN。
RNN / LSTM循环网络
按顺序一个字一个字读，边读边记。问题：读到后面忘了前面，而且没法并行（必须一个接一个）。这就是 Transformer 出现的原因。
Embedding嵌入 / 向量化
把词、句子、图片变成一串数字坐标，意思相近的坐标就靠得近。“猫”和“小猫”距离近，“猫”和“混凝土”距离远。作用：这是“语义”能被计算的前提。搜索、推荐、聚类、大模型，全靠它。
微调 / 蒸馏 / 量化Fine-tune / Distill / Quantize
微调：拿现成的大模型，用自己的数据再教一下，让它变成“你们行业的专家”。蒸馏：让小的学大的，把本事压缩过去。量化：把参数从 16 位小数压成 4 位整数，模型小一半、快一倍，稍微笨一点点。作用：都是为了让模型能塞进手机、能便宜地跑。

Transformer：现在所有大模型的同一个地基

ChatGPT、翻译、代码补全、你手机里的输入法联想——背后是同一个结构。

它解决了什么问题：以前的 RNN 像一个人一个字一个字读，读到句末已经忘了句首，还没法并行（必须排队）。Transformer 让一句话里所有词同时互相看一遍，谁重要就看谁多一点。既能并行（快），又能记住远距离关系（准）。

核心比喻：一场圆桌会议。每个词都是参会者，手上有一张问题卡（Query）、一个名牌（Key）、一份发言稿（Value）。每个人拿自己的问题去对所有人的名牌，谁对得上就重点听谁的发言。“它”指谁？——问一圈，发现“小猫”对得最上，那就听“小猫”的。这就是“消歧”。

概率分布
Token / 分词器Tokenizer
模型不认字，只认编号。分词器把“今天天气不错”切成 ["今天","天气","不错"] 再换成 [2345, 889, 102]。作用：token 是模型的“最小计量单位”，也是你付钱的计算单位——中文一个字常常就是一个 token，所以中文比英文贵。
Embedding 层嵌入
一张巨大的表，每个 token 编号对应一个几千维的向量。作用：把“符号”变成“坐标”，让语义可以算加减。“国王 − 男人 + 女人 ≈ 女王”就是这个空间里的真实几何关系。
位置编码Positional Encoding
因为所有词是同时进去的，模型不知道谁在前谁在后。“猫咬狗”和“狗咬猫”对它来说会是同一堆东西。作用：给每个位置发一个“座位号”，顺序信息才不丢。现代模型多用 RoPE（旋转位置编码），效果更好。
自注意力 Q / K / VSelf-Attention
每个词算出三个向量：Q 我要找什么、K 我能提供什么、V 我实际的内容。
然后把 Q 和所有词的 K 做点积 → 得到相似度 → 归一化成权重（softmax）→ 用权重把所有 V 加权求和。
白话：“因为”这个词问“我指代谁？”，跟“小猫”的 K 匹配度最高，于是把 80% 的注意力放在“小猫”身上。作用：让模型自己决定该看哪儿，而不是靠人写规则。
多头注意力Multi-Head Attention
同时开 8 个、32 个“视角”并行做上面那件事。有的头专门盯语法主谓，有的盯指代，有的盯情绪。作用：一个角度看问题容易漏，多角度同时看就全面了。
残差连接 + LayerNormResidual + Normalization
输出 = 输入 + 这一层的改动；再做一次数值归一化。作用：保证信息不会在层层传递中被磨没，也不会数值爆炸。这是能堆几十上百层的前提——没有它，深了必然训练失败。
前馈网络 FFNFeed Forward Network
对每个位置单独做一次“升维 → 激活 → 降维”的加工。作用：注意力负责“交流信息”，FFN 负责“各自思考消化”。模型里一大半参数都在这里，很多人认为这里是“知识存储”的地方。
三种形态Encoder / Decoder
只用编码器（BERT 类）：擅长“理解”——分类、抽取、搜索排序。
只用解码器（GPT / Llama / Qwen）：擅长“往下写”——聊天、写代码、推理。现在主流全是这一类。
编码器+解码器（T5、翻译模型）：输入一段、输出一段，适合翻译、摘要、语音识别。

这些词你必须知道，不然聊 AI 会露怯

上下文窗口Context Window
一次最多能塞多少 token（比如 128K）。作用：决定它能“一次看多长的材料”。为什么长文档贵？因为自注意力的计算量是长度的平方——长度翻倍，计算量四倍。这是 Transformer 最大的软肋。
KV Cache键值缓存
生成时，前面算过的 K 和 V 存起来不重算。作用：没有它，每多吐一个字都要把全文重算一遍，根本没法用。代价是吃显存——大模型服务贵，一大半贵在这上面的显存。
温度 / top-pTemperature / Nucleus Sampling
控制“下一个词”抽签时有多放飞。温度低（0.2）→ 只挑最可能的，稳定但死板；温度高（1.0+）→ 更敢挑冷门词，有创意但容易胡说。作用：写代码调低，写文案调高。
幻觉Hallucination
一本正经地编。原因很朴素：它本质是在“猜下一个最像的词”，不是在查数据库。它没有“我不知道”这个强约束，所以会顺着语言惯性编下去。对策：让它先检索资料再回答（RAG）、允许调用工具/搜索、要求给出来源、关键结论人工复核。
RAG检索增强生成
先从你的资料库里搜出相关段落，再把这几段塞进提示词让模型基于它们回答。作用：让模型说“你们公司的事”，还能大幅减少幻觉、方便更新知识（不用重训模型）。企业落地大模型，90% 用的是这条路。
MoE混合专家
模型里有很多“专家小组”，每次只叫醒其中两三个干活。作用：参数总量很大（知识多），但每次只算一小部分（省算力）。现在很多大模型都用这招。
Prompt / Agent提示词 / 智能体
Prompt 就是你怎么问，问得好坏能差出一个量级。Agent 是让模型自己拆步骤、调工具、看结果、再调整，循环把活干完——从“问答机”变成“能办事的实习生”。
用在哪：翻译（同一个结构换数据就行）、代码补全、客服机器人、会议纪要与摘要、法律合同比对、医疗报告初筛、手机输入法下一词预测、图片描述生成（多模态）、语音转文字（编码器+解码器）。它之所以叫“地基”，是因为换数据、换规模就能干几乎任何“从一段内容到另一段内容”的活。
7

数据仓库：把一堆流水账，变成能拍板的数字

这是把前面所有东西攒下来的数据，真正变成钱的一步。

先分清两个场景，这是全章的关键：
OLTP（联机交易）= 前台收银台。一次只动一两行（扣库存、加订单），要求毫秒级、绝不出错、几千人同时用。MySQL / PostgreSQL 干这个。
OLAP（联机分析）= 后台算账。一次扫几千万行做汇总（“上个月华东区退货率多少”），要求吞吐量、不在乎慢几秒。

为什么不直接在收银库上算报表？因为一条大查询会把数据库的 CPU 和 IO 全占了，收银台就卡死——相当于老板在大堂搬张桌子算账，客人全堵门口。所以必须把数据搬到一个专门的仓库里去算。这就是数据仓库存在的唯一理由。
ETL / ELT抽-洗-装
E 抽取（从业务库、日志、Excel、第三方 API 拿数据）、T 清洗转换（统一字段、去重、补空值、换算口径）、L 装载（写进仓库）。
现在多是 ELT：先原样装进去，再用仓库的算力洗——因为云仓库算力强，先存后洗更灵活、能留原始痕迹。
分层：ODS → DWD → DWS → ADS
这是数据仓库的骨架，把“做菜的工序”拆开，每层只干一件事。不分层的后果是：一张报表一套 SQL，逻辑散了，谁也说不清哪个数对。
ADS 应用层　直接喂给看板 / 报表 / 接口的结果表
DWS 汇总层　按天、按用户、按商品轻度聚合，避免重复算
DWD 明细层　清洗后的干净明细：谁、何时、在哪个店、买了什么、多少钱
ODS 原始层　从业务系统原样搬过来的“原始档案”，不加工、可回溯
事实表Fact Table
记录“发生了什么”的表：一行就是一次事件，带一堆数字（金额、数量、时长）。作用：所有指标都从它算出来。它会长得飞快（一天几千万行）。
维度表Dimension Table
描述“谁、什么、哪里、何时”的表：用户表、商品表、门店表、日期表。作用：让你能“按省份看”“按品类看”“按新老客看”。事实表只有 ID，靠它翻译成人能看懂的名字。
星型模型 / 雪花模型Star / Snowflake Schema
一张事实表放中间、一圈维度表围着，像颗星星（星型）；维度表再拆细就是雪花。作用：查得快、结构清晰。星型是数仓里最常用的形状。
缓慢变化维SCD
用户去年在杭州、今年搬到上海，去年的订单该算杭州还是上海？作用：决定“历史要不要保留当时的真相”。最常见的做法是留两行（生效时间区间），这样既能按当时看，也能按现在看。
指标 / 口径Metric / Definition
口径就是“这个数到底怎么算”的书面约定。“活跃用户”是登录算、打开算、还是下单算？“GMV”含不含退款、含不含运费？作用：口径不统一，两个部门能报出两个数，然后在会上吵两小时。数据仓库最值钱的产出，往往不是表，而是统一口径。
数据质量Data Quality
空值、重复、手机号写成 11 个 1、金额是负数、日期跑到 2099 年。作用：脏数据进去，垃圾结论出来（Garbage in, garbage out）。所以每层都要有校验规则和告警。
调度 / DAGScheduling
每天凌晨 2 点自动开跑，而且“A 表跑完才能跑 B 表”这种依赖要自动管——这个依赖关系就是有向无环图（DAG）。作用：没有调度，几万个任务靠人点，天亮也跑不完。工具：Airflow、DolphinScheduler、dbt。
血缘Lineage
“这个报表的数是从哪几张表、哪个字段算来的”的完整链路图。作用：出了问题能一路往上追；要改逻辑能知道会影响谁（不然改一个字段崩十个看板）。
数据湖 / 湖仓一体Data Lake / Lakehouse
湖：把原始数据（日志、图片、JSON、埋点）先原样倒进去，便宜、能装一切，但容易变成“数据沼泽”（倒进去没人管）。湖仓一体：在湖上套一层仓库的管理规范（表格式、schema、事务），兼具便宜和好用。现在新建基本都走这条。
实时数仓Kafka + Flink
不用等凌晨跑批，数据一来就流过去算，秒级出结果。作用：大屏实时成交额、风控拦截、直播看板。代价是复杂度和成本高得多，不是所有场景都值得。

举一个具体的例子：算 GMV（成交总额）
先把问题问清楚：拍下就算，还是付款才算？退款要不要扣？跨天支付记在哪天？含不含运费？这四个问题不定下来，五个人能算出五个数。
定好之后写进 DWD 的口径文档，DWS 按“天 × 品类 × 地区”预聚合，ADS 出“昨日 GMV 环比”的看板。全公司都读同一张 DWS，口径才不会打架。
这就是数仓真正的价值：不是存数据，是让所有人对同一件事有同一个数。

  1. 组成原理：摄像头里的 CMOS 把光转成电信号，靠 ADC 变成数字像素；树莓派/工控机用 CPU 做通用逻辑、用 GPU/NPU 做并行加速。内存够不够，直接决定能不能跑 30 帧。
  2. 数据结构：一帧图像在内存里就是一个大数组；68 个关键点存成数组；为了防抖动，用队列存最近 30 帧算滑动平均；多路摄像头排任务用堆按优先级调度。
  3. 计算机网络：网络摄像头通过 RTSP/HTTP 把视频流推过来；报警事件用 MQTT/HTTPS 上报云端；手机 App 靠 WebSocket 或推送拿到实时告警。延迟高，报警就晚半秒。
  4. 单片机：判定为疲劳 → GPIO 拉高蜂鸣器、PWM 调震动马达强度、串口通知座椅模块；按键用中断响应；看门狗防止长期运行死机。这一层是“算法变成动作”的最后一厘米。
  5. AI：如果只做 EAR 阈值，那还是规则；加上 CNN 做眼部状态分类、或做人脸检测定位，才算 AI。训练时盯 loss、防过拟合，上线时盯误报率——误报一次，司机就把功能关了，这比准确率更致命。
  6. Transformer：如果想做“驾驶行为时序分析”（连续 5 分钟的头部姿态 + 眼动 + 车道偏移），Transformer 能同时看到整段序列的关联，比逐帧判断准得多；代价是算力和延迟。
  7. 数据仓库：每天的检测记录、误报标记、车型、驾驶员 ID、路段，进 Kafka 落 ODS，清洗成 DWD，汇总成“某车型每百公里误报次数”的 DWS，最后出 ADS 看板。产品经理靠这张表决定下一版改什么。
看明白了吗：没有任何一块知识是孤立的。摄像头是物理，传到电脑是网络，处理是数据结构和算法，判断是 AI，动作是单片机，复盘是数仓。你能把这条线讲通，就比会背十个名词的人强得多。

如果你要学，按这个顺序

不按难度，按“能不能马上用上”排序。

  1. 先补数据结构 + 网络。这两块投入产出最高。知道 B+ 树能解释 90% 的数据库慢查询；知道四层模型能解释 90% 的“网不好”。
  2. 再补组成原理，但只补到你够用为止。会讲清“缓存/内存/硬盘/GPU 为什么这么重要”就够，不用会画电路。
  3. 单片机和 AI 挑一个当手感。想摸硬件就先点灯、读传感器、做个小车；想搞算法就先跑通一个分类任务，看 loss 掉下来。别两个同时学。
  4. Transformer 别从公式入手。先把“每个词开会、投票决定听谁”这个画面记住，再回头看 Q/K/V，你会发现公式只是把这个画面写成数学。
  5. 数仓放在最后但一定要学。它是把技术变成“老板看得懂的数字”的那道桥，也是很多技术人往上走的分水岭。
最后一句实话：这些名词听起来吓人，拆开全是“为了省时间”“为了不出错”“为了让人看懂”这三种需求的产物。你只要能回答一个问题——“这个东西如果不存在，会有什么麻烦？”——你就真懂了。
